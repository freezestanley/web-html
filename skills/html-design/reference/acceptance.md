# 验收协作

`html-design` 在交付后进入待修复状态，直到 `web-html` 明确告知验收通过。

## 收到验收问题时

1. 只改受影响部分，不顺手重构
2. 保持既有技术路线和目录结构
3. 视觉方向问题优先回传设计层处理
4. 资源、组装、代理问题由本层直接修复
5. 修完后只回报三件事：改了什么、还剩什么、建议复测哪里

## 禁止项

- 未收到验收反馈就自行二次优化
- 把修复扩展成重设计
- 新增依赖却不更新说明
- 绕过 `web-html` 直接向用户确认完成

## 结束条件

只有当 `web-html` 明确表示“验收通过，且用户确认”时，本轮工作才算结束。
