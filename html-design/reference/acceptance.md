# 验收协作

`html-design` 自己不结束任务。产物交付后必须等待 `web-html` 通过 CDP 验收，并根据反馈迭代。

## 修复原则

收到验收问题时：

1. **只修受影响的部分** — 不要无关重写、不要顺手重构
2. **保持既有结构** — 不改项目目录、不换技术栈、不调视觉方向
3. **区分责任归属**
   - 视觉 / 文案 / 布局问题 → 优先回传 `design-taste-frontend` 处理
   - 资源合规 / 产物组装 / 代理配置 → 由本 skill 直接修复
4. **修完即回报** — 列出本次修改点 + 仍存在的已知限制，等待下一轮验收

## 禁止项

- 不要在未收到 CDP 反馈时自行"优化"页面
- 不要把验收修复变成二次设计
- 不要在修复过程中引入新的 CDN 依赖而不更新清单
- 不要绕过 `web-html` 直接与用户确认"改好了"

## 完成信号

只有当 `web-html` 明确告知"CDP 验收通过、用户已预览确认"后，本 skill 的工作才算结束。
在此之前，始终处于待命状态。
