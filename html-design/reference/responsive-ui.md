# 多端适配与 UI/UE 基线

本文件定义 `html-design` 交付物在 H5 / PC 双端必须达到的体验底线。
视觉方向来自 `design-taste-frontend`，本文件约束的是"无论什么风格都必须做到"的通用标准。

## 适配策略

- **移动优先**：基础样式面向 ≤ 375px 视口编写，断点向上叠加
- **必覆盖断点**：
  - H5：320px / 375px / 414px（主流手机）
  - 平板：768px / 1024px
  - PC：1280px / 1440px / 1920px
- **内容不溢出**：任意断点下水平无滚动条、文字不被裁切、触摸目标不被遮挡
- **图片响应式**：使用 `max-width: 100%; height: auto;` 或 `<picture>` / `srcset`，禁止固定宽高导致变形
- **字体可读**：H5 正文 ≥ 14px，PC 正文 ≥ 16px；行高 ≥ 1.5；避免在小屏上使用超细字重

## H5 专项

- 触摸目标最小 44×44px，间距 ≥ 8px
- 表单控件适配移动端键盘类型（`inputmode` / `type`）
- 避免 hover-only 交互；所有 hover 效果必须有对应的 active/focus 状态
- 长列表使用虚拟滚动或分页，禁止一次性渲染 > 100 条
- 横竖屏切换后布局不破；如有锁定方向需求，明确记入已知限制
- 安全区适配：底部操作栏预留 `env(safe-area-inset-bottom)`

## PC 专项

- 最大内容宽度建议 1200–1440px，居中并留白
- 支持键盘 Tab 导航，焦点顺序合理、可见
- 悬停状态提供即时反馈（≤ 100ms）
- 大数据表格支持排序 / 筛选 / 横向滚动，不强制换行挤烂布局
- 鼠标指针在可交互元素上切换为 pointer

## UI 质量底线

- **一致性**：颜色、字号、间距、圆角、阴影全部走 token，禁止散落魔法值
- **层次清晰**：信息层级通过字号 / 字重 / 颜色对比度区分，而非仅靠位置
- **留白充足**：模块间距 ≥ 一个基准 spacing token；拥挤即失败
- **文案可读**：标题与正文对比度 ≥ 4.5:1（WCAG AA）；禁用纯灰底配浅灰字
- **状态完整**：每个交互组件必须实现 default / hover / active / focus / disabled / error 六态
- **加载与空态**：异步内容必须有 loading 骨架 / spinner；空数据必须有引导文案，禁止空白

## UE 质量底线

- **首屏可用**：关键内容无需 JS 即可渲染；JS 仅增强交互
- **反馈即时**：点击 / 提交后 100ms 内给出视觉反馈（按压态 / 加载态）
- **错误可恢复**：表单校验失败时定位到首个错误字段并给出明确提示
- **返回路径**：多级流程必须有明确的返回 / 取消入口
- **无障碍基础**：语义化标签 + alt + label + focus 管理 + ARIA（仅在原生语义不足时使用）
- **性能感知**：LCP ≤ 2.5s、INP ≤ 200ms、CLS ≤ 0.1（如项目有更高要求以项目为准）

## 验收检查项

CDP 验收时除功能验证外，至少抽查：

1. 375px + 1440px 两个断点截图，确认布局完整
2. 触摸目标尺寸合规（H5）
3. 键盘 Tab 走完一轮核心流程（PC）
4. 网络节流到 Slow 3G 下首屏仍可渐进呈现
5. 表单提交失败时的错误提示可达

未通过任一项即视为未完成，按 [acceptance.md](./acceptance.md) 修复。
